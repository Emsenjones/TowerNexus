

# Task 003 - AStar Pathfinding

## 1. Overview

This task introduces the grid-based A* pathfinding system for TowerNexus.

The purpose of this task is to:

- Calculate valid monster movement paths
- Support runtime walkability changes
- Support tower placement validation
- Provide reusable pathfinding services for future systems

This task focuses only on pathfinding calculation and path validation.

This task does NOT include:

- Monster movement
- Monster state machine
- Monster combat
- Monster death logic
- Runtime monster path following
- Dynamic path recalculation notifications

These systems will be implemented in later tasks.

This task is designed based on:

- 00_ProjectOverview.md
- 03_MonsterSystem.md

This document only defines the implementation scope of the current task.

## Related Tasks

This task is closely related to:

- Task_002_MonsterWaveSpawner
- Task_004_MonsterMovement
- Task_006_PathBlockingValidation

Relationship:

- MonsterWaveSpawner provides runtime monster spawning before path requests begin.
- MonsterMovement will consume paths generated by this task.
- PathBlockingValidation will reuse runtime path validation APIs from this task.

# 2. Goal

Implement a reusable A* pathfinding service.

The system should support:

- Grid-based pathfinding
- Runtime path calculation
- Runtime path validation
- Runtime walkability queries
- Future system extensibility

---

# 3. Runtime Architecture

Recommended runtime structure:

| Layer | Responsibility |
|---|---|
| Map System | Provides runtime node data and walkability |
| AStarPathfindingService | Calculates valid paths |
| Monster System | Uses calculated paths for movement |
| Tower Deployment System | Uses path validation before placement |

The pathfinding system should remain independent from monster runtime logic.

---

# 4. Pathfinding Rules

## 4.1 Movement Rules

Current pathfinding rules:

- Horizontal movement allowed
- Vertical movement allowed
- Diagonal movement disabled
- Movement calculated on XZ plane
- Path nodes use NodeBehaviour center positions

---

## 4.2 Walkability Rules

A node is considered valid for pathfinding when:

- Node exists
- Node.IsWalkable == true

Non-walkable nodes must be excluded from pathfinding.

---

# 5. AStarPathfindingService

## 5.1 Description

AStarPathfindingService is responsible for:

- Finding valid paths between nodes
- Checking path existence
- Supporting runtime path validation
- Supporting future runtime repathing

The service should not contain:

- Monster movement logic
- Tower logic
- Animation logic
- Combat logic

---

## 5.2 Required APIs

Recommended APIs:

```csharp
List<NodeBehaviour> FindPath(
    NodeBehaviour startNode,
    NodeBehaviour targetNode
)
```

```csharp
bool HasValidPath(
    NodeBehaviour startNode,
    NodeBehaviour targetNode
)
```

---

# 6. Runtime Pathfinding Flow

Recommended runtime flow:

```text
Request Path
→ Validate start node
→ Validate target node
→ Run A* search
→ Build final node path
→ Return path result
```

---

# 7. Neighbor Search Rules

The pathfinding system should support neighbor node searching.

Current neighbor rules:

- Up
- Down
- Left
- Right

Diagonal neighbors are intentionally disabled.

Neighbor searching should use the existing Map System node structure.

---

# 8. Path Result Structure

The final path result should:

- Return ordered node list
- Start from current node
- End at target node

Recommended structure:

```text
Start Node
→ Node A
→ Node B
→ Node C
→ Target Node
```

---

# 9. Runtime Path Validation

The pathfinding system must support runtime path validation.

This functionality will later be used by Tower Deployment System.

Recommended validation behavior:

```text
Tower Placement Preview
→ Simulate blocked nodes
→ Check path existence
→ Allow or reject placement
```

This task only implements path validation support.

Actual tower placement integration is implemented later.

---

# 10. Temporary Walkability Validation

The pathfinding system should support temporary blocked node simulation.

Recommended behavior:

```csharp
bool HasValidPath(
    NodeBehaviour startNode,
    NodeBehaviour targetNode,
    IReadOnlyCollection<NodeBehaviour> temporaryBlockedNodes
)
```

Purpose:

- Avoid modifying runtime Node.IsWalkable directly during validation
- Prevent temporary validation state corruption
- Support future runtime simulation systems

---

# 11. Runtime Constraints

Current constraints:

- Only supports single-layer grid pathfinding
- Only supports ground movement
- Only supports rectangular node traversal
- Does not support terrain cost weighting yet
- Does not support dynamic avoidance yet

Future versions may support:

- Terrain weights
- Flying movement
- Dynamic obstacle avoidance
- Smart crowd movement
- Path optimization

# 14. Acceptance Criteria

This task is considered complete when:

1. AStarPathfindingService exists.
2. The system supports grid-based A* pathfinding.
3. The system supports horizontal and vertical traversal.
4. Diagonal traversal is disabled.
5. FindPath returns ordered node paths.
6. HasValidPath correctly validates path existence.
7. Non-walkable nodes are excluded from pathfinding.
8. Temporary blocked node validation is supported.
9. The system remains independent from monster runtime movement.
10. No monster movement logic is implemented yet.
